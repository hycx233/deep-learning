## 最简 Issue / PR 写法

普通 issue 可以直接复制上面的对应条目。额外问题使用以下格式即可：

```markdown
负责人：
目标：
输入：
输出：
完成日期：
依赖 issue：

验收：
- [ ] 能运行，并附命令
- [ ] 保存结果，附一张图或一组数值
```

PR 模板：

```markdown
Closes #实际 issue 号

完成了什么：
运行命令：
结果/代表图：
尚存问题（没有则删除）：
```

共同报告子 PR 用 `Refs #实际 issue 号`，由最后完成者关闭 issue。审核只找一名其他成员，不把所有 PR 都压给组长；检查重点是能运行、输入输出一致、结论与图表一致。

建议只设三个里程碑：9/21 跑通首版、9/26 结果定稿、9/28 可提交。9/29—9/30 不预排功能，用作机动；10/1 为本组内部提交日。

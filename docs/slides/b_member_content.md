## 第 1 页：用小型 CNN 做三分类（约 40 秒）

**页面主句：从 128×128 接触图中提取局部形态，输出三类结构的分数。**

建议画面：`128×128 输入 → 三个卷积模块 → 全局平均池化 → 三分类输出`。
输出旁写 OPCID、CHIN、CHID 三个标签即可，不展开三类的生物学机制。

口播：

> 我的部分先做有监督分类。每个已知结构对应一张共享处理后的 128 乘 128 接触图，
> 模型输出三类结构的分数。我们用了三个卷积模块提取局部形态，再用全局平均池化
> 汇总特征。因为原始标注只有三百四十四个结构，所以选择小型 CNN，让模型规模
> 与数据量相称。同一结构的两个重复和相互重叠的窗口保持在同一集合，避免相似输入
> 同时进入训练和评价，造成成绩偏高。

准备备注：模型见 [src/cnn.py](../../src/cnn.py) 的 `SmallCNN`。
真实通道数为 16/32/64，卷积后接 BatchNorm、ReLU 和池化，最后全局平均池化与线性层；
无需在投影片逐项列出。正式共享划分与空间分组见 [分类模块说明](../分类模块说明.md)。
两个重复形成 688 个窗口，但不能讲成 688 个独立结构。

## 第 2 页：损失、反向传播与模型选择（约 45 秒）

**页面主句：加权交叉熵处理类别不均衡，验证集 Macro-F1 选择最佳轮次。**

建议画面：本段唯一的短代码，下方配“训练更新参数；验证选择权重；测试留到最终评价”。

```python
logits = model(features)
loss = criterion(logits, labels)
if training:
    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    optimizer.step()
```

这是 `run_epoch` 的连续真实节选，省略批次读取、设备移动和指标汇总等上下文。
不逐行翻译，只用它说明“一次预测、计算损失、反向传播、更新参数”的训练循环。

口播：

> 训练使用常规的前向计算、损失、反向传播和参数更新。这里三类样本数量不均衡，
> 所以交叉熵的类别权重只根据训练集计算，增加少数类在损失中的作用。每轮训练后，
> 我们在验证集上计算 Macro-F1，也就是先分别算三类 F1，再等权平均，用它保存最佳
> 权重。验证阶段不更新参数，测试集也不参与轮次选择。这样后面的最终测试才能
> 反映模型在保留样本上的表现。

准备备注：节选和训练/验证分支见
[train_classifier.py](../../scripts/train_classifier.py) 的 `run_epoch`；同文件 `main`
创建 `CrossEntropyLoss(weight=class_weights)` 并按验证 Macro-F1 保存 `best.pt`。
权重计算见 [src/cnn.py](../../src/cnn.py) 的 `compute_class_weights`，
指标见 [src/metrics.py](../../src/metrics.py) 的 `macro_f1`。

## 第 3 页：测试集与简单基线（约 50 秒）

**页面主句：逻辑回归基线优于当前 CNN；CHID 仍是明确短板。**

| 固定测试方法 | n | Accuracy | Macro-F1 |
| --- | ---: | ---: | ---: |
| 小型 CNN | 104 | 0.5096 | 0.3454 |
| 多数类（CHIN） | 104 | 0.7308 | 0.2815 |
| 逻辑回归 | 104 | 0.8365 | 0.5644 |

测试逐类支持数为 OPCID 20、CHIN 76、CHID 8。CNN 的逐类 F1 为 0.4062、0.6299、0；
逻辑回归为 0.8000、0.8931、0。每类 3 个独立结构位置的解释图保存在
[`test_evaluation/gradcam`](../results/classifier/test_evaluation/gradcam/)，另有混淆矩阵和失败列表。

口播：

> 我们在训练完成后使用固定测试集做了一次最终评价。CNN 的 Accuracy 是百分之五十一，
> Macro-F1 是零点三四五；总是预测训练多数类 CHIN，Accuracy 更高、Macro-F1 更低。
> 将接触矩阵展平后拟合的逻辑回归两项指标都高于 CNN，所以不能说当前 CNN 优于简单分类器。
> 三个方法都没有识别出 CHID。测试集中 CHID 只有八个窗口，对应四个位置，因此这个结果
> 需要谨慎解释。我们也保存了错误样本和 Grad-CAM，展示模型具体混淆在哪里。

准备备注：这些数字来自 B 的新复跑 checkpoint，输入与共享划分同组长交接一致，但权重不同；
勿与组长原 checkpoint 的验证成绩混写。分析入口为
[`analyze_classifier.py`](../../scripts/analyze_classifier.py)，完整 JSON、CSV 和图见
[`test_evaluation`](../results/classifier/test_evaluation/)。Grad-CAM 针对预测类别；它说明模型
响应区域，不证明生物学机制。

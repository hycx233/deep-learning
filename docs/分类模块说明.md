## 运行

```bash
# 1. 先按共享预处理说明生成 classification/windows.csv 与 windows.npz
# 2. 真实训练：只用训练集，用验证集选轮次与早停
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 \
python scripts/train_classifier.py \
    --windows-csv outputs/preprocessing/default/classification/windows.csv \
    --arrays-npz outputs/preprocessing/default/classification/windows.npz \
    --out-dir outputs/classifier/real_seed20260918 \
    --epochs 30 --patience 8 --seed 20260918 --device cpu

# 3. 只导出验证集；最终测试集推理由 #4 执行
python scripts/predict_classifier.py \
    --checkpoint outputs/classifier/real_seed20260918/best.pt \
    --windows-csv outputs/preprocessing/default/classification/windows.csv \
    --arrays-npz outputs/preprocessing/default/classification/windows.npz \
    --split val --device cpu \
    --out-csv outputs/classifier/real_seed20260918/predictions_val.csv
```

常用参数：`--epochs`、`--batch-size`、`--lr`、`--seed`、`--device`、`--patience`、
`--windows-csv`、`--arrays-npz`、`--out-dir`。路径都可以指定，脚本不含任何人的绝对路径。

输出（`outputs/` 已被 `.gitignore` 排除）：

```text
outputs/classifier/<运行名>/
├── best.pt                  # 按验证 Macro-F1 选出的权重
├── train_log.txt            # 逐轮记录
├── run.json                 # 运行命令、随机种子、数据划分、参数、代码版本
├── splits.csv               # 本次使用的 train/val/test 划分，评价时沿用
└── predictions_<split>.csv  # 逐样本判定结果与 .summary.json
```

`splits.csv` 是刻意保存的：推理入口默认读取权重同目录下的这一份，而不是按种子重新划分。
重新划分会得到不同的集合，那样"测试集结果"就不是同一批样本，指标不可比；若该文件缺失，
推理入口会打印警告后按种子重划，并在窗口与划分列表对不上时直接报错。

## 输入格式约定

训练与推理入口只需要拿到两份文件，读取逻辑集中在 `src/classifier_data.py` 的
`load_dataset`，#2 的产物已按此约定生成，可原样读取；后续若改变格式，只需改这一处。

**windows 表（CSV）**：至少包含 `window_id, chrom, start, end, sample_id, condition,
replicate`，以及类别列（优先 `label`，其次 `type`），还需要能判定同一结构的分组列
`structure_id`（或 `structure`）；若表里已经有 `split` 列（#2 给出的分组列表），则直接沿用。

**数组文件（`.npz`）**：`X` 为 float32 的 `N x 128 x 128`，`y` 为 int64 的 `N`，行序与
windows 表一致。坐标沿用 0-based、左闭右开。

## 与 #2 的分组口径

1. **重叠窗口按坐标连通分量分组，实测可行。** 344 条结构的 24 kb 窗口在真实坐标下只形成
   **59 个重叠连通分量**（最大 20 条结构）：343 个相邻中心间距里有 **16.9% 超过 24 kb**，
   正是这些断点把基因组切开，并没有连成整条染色体。#2 的 `src/window_splits.py` 据此划分出
   241 / 51 / 52 个位置（两个重复共 482 / 102 / 104 个窗口），三个集合都含三类结构，跨集合
   共享的 100 bp bin 为 0。**窗口表里的 `split` 列必须原样沿用，不要自行重划。**
   这一条推翻了本模块早期基于合成样例的判断：样例把结构均匀铺在 13,454 bp 间距上，窗口
   首尾相接串成一片，才得出"只能按结构身份分组、否则整条染色体并成一组"的错误结论。
   `src/classifier_data.py` 里按结构身份分组的逻辑因此只作为缺 `split` 列时的兜底，不代表正式口径。
2. **类别不均衡与集合划分。** 68 / 250 / 26 的比例下，验证集和测试集都要有三类样本，
   训练入口会在某类为空时直接报错，而不是照常训练出一个无法评价的模型。

## #4 测试集评价与解释（2026-09-29 已完成）

正式分析使用 B 本地复跑生成的权重，并显式传入同次训练生成的 `splits.csv`。输出命令如下；
原始运行的逐项记录与摘要已保存到 `docs/results/classifier/test_evaluation/`。

```bash
OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 \
python scripts/train_classifier.py \
  --windows-csv outputs/preprocessing/default/classification/windows.csv \
  --arrays-npz outputs/preprocessing/default/classification/windows.npz \

  --windows-csv outputs/preprocessing/default/classification/windows.csv \
  --arrays-npz outputs/preprocessing/default/classification/windows.npz \

  --checkpoint outputs/classifier/b_retrain_seed20260918/best.pt \

```

分析入口拒绝缺失或不匹配的划分与预测表；多数类基线只使用训练集众数，逻辑回归只在训练集
拟合，二者都只在固定 test 上比较。此次 CNN 的 Accuracy/Macro-F1 为 0.5096/0.3454；
多数类基线为 0.7308/0.2815；逻辑回归为 0.8365/0.5644。CNN 的 Macro-F1 高于多数类基线，
但两项指标都低于线性基线，且 CHID 的 8 个测试窗口无一识别正确。结果、矩阵、失败列表、
每类 3 个不同结构位置的 Grad-CAM、输入及代码指纹见 `docs/results/classifier/test_evaluation/`。
Grad-CAM 针对模型预测类别，不作为因果解释。
